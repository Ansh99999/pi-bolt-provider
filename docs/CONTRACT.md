# Module contract

All imports between source files use explicit `.ts` extensions. No runtime npm dependencies. Host imports come from `@earendil-works/pi-coding-agent` and `@earendil-works/pi-tui` (both 1.4.0 for development). `src/types.ts` owns shared data shapes; do not change it without telling the orchestrator.

## Version 0.2 update

The changes here supersede older add-only and scope-append descriptions below. `provider-list.ts` provides the themed searchable browser with edit/delete actions; storage lists only native stored sign-ins and extension additions. `loadProviderDraft` restores editable data, `saveProvider(draft, reservedIds?, agentDir?, scopeBase?)` supports a stable `editingId` and a native `preserveConnection` mode, and `deleteProvider` removes only the target's saved files and settings entries. Native edits preserve credentials, provider fields, model definitions, and unrelated model overrides.

The command snapshots active model choices before saving, persists selected models while preserving other providers, refreshes the catalog without network, and uses `ctx.switchSession` to resume the same conversation with its saved scope. All work after replacement uses the fresh context; the old command always exits. Temporary sessions and explicit CLI/project overrides are reported. This work is command-only; the entry point still only registers the command.

`ProviderModel.thinkingLevelMap` follows Pi's native seven-level mapping. `thinking.ts` validates advertised maps/effort lists, with null for unsupported levels. The wizard keeps explicit metadata, uses consistent exact catalog matches when metadata is absent, and supports T to edit thinking support/levels. It never guesses capabilities from a model name. Skins and native streaming stay unchanged.

## Entrypoint and command (orchestrator)

`index.ts` imports only ExtensionAPI as a type and registers /provider. Its handler dynamically imports `src/command.ts`, which loads storage and a native custom screen, presents Current provider/Add provider/List Providers, saves confirmed drafts, awaits `ctx.modelRegistry.refresh({ allowNetwork: false })`, then uses `pi.setModel` for a chosen global default. It must guard non-TUI execution and block duplicate wizard openings.

## Endpoints and model discovery (core worker)

Own `src/endpoints.ts`, `src/network.ts`, `tests/endpoints.test.ts`, `tests/network.test.ts`.

Export `normalizeEndpoint(input: string, method: Method): Endpoint`, `providerId(name: string, baseUrl: string): string`, `displayProviderName(name: string, baseUrl: string): string` from endpoints. Use https when scheme omitted; preserve explicit http for local endpoints; reject other schemes, URL userinfo/query/fragment, control chars. Handle trailing slash, /v1, /v1beta, full supported method paths without duplicating them. Preserve gateway path prefixes. OpenAI SDK base includes /v1, Anthropic SDK base excludes /v1 (SDK appends /v1/messages), Google base includes explicit /v1 or /v1beta and uses its native API. UI's generativecontent label is a protocol choice; actual Google path is /models/{model}:streamGenerateContent. Reserved prototype-like provider IDs must be rejected.

Export `fetchModels(draft: ProviderDraft, signal?: AbortSignal): Promise<ProviderModel[]>` and `checkKey(draft: ProviderDraft, signal?: AbortSignal): Promise<KeyCheck>` from network. Use selected key, `profileHeaders` + custom headers, protocol-specific auth; do not use a proxy or custom chat transport. Network happens only on explicit user action. Use abortable timeouts, bound response bytes and model count/pagination, refuse redirects that could leak keys. Support OpenAI {data:[{id}]} and Google {models:[{name,...}]} and Anthropic list pagination. Do not return bodies in errors. Empty model listing or unsupported /models must be explained without declaring a valid key invalid. Network tests use temporary local servers/dummy keys. Avoid retaining response data.

## Headers (header worker)

Own `src/headers.ts`, `docs/header-profiles.md`, `tests/headers.test.ts`. Export `SKINS: readonly { id: Skin; label: string; description: string }[]`, `profileHeaders(skin: Skin, method: Method): Record<string,string>`, `validateHeader(name: string, value: string): void`, and `literalConfigValue(value: string): string`. Research Claude Code, Codex CLI, OpenCode and Pi separately using official public source/docs or installed public program code. Cite sources and distinguish branding headers, auth/body details, dynamic identities. Defaults must not invent real account/session/organization IDs or bearer tokens. Client versions must be clearly pinned/documented and user-overridable through custom headers. Pi profile supplies no overrides so Pi's normal defaults apply. Reject invalid header names/control chars; disallow transport-managed content-length/host/connection/transfer-encoding and authorization/api-key overrides so selected key owns authentication. `literalConfigValue` escapes Pi interpolation ($ as $$ and initial ! as $!) so user strings cannot execute commands or resolve unintended env variables.

## Storage (storage worker)

Own `src/storage.ts`, `tests/storage.test.ts`. Export `getStorageDir(): string` (honor PI_CODING_AGENT_DIR, otherwise ~/.pi/agent), `loadSavedProviders(agentDir?: string): Promise<ProviderSummary[]>`, `saveProvider(draft: ProviderDraft, reservedIds?: readonly string[], agentDir?: string): Promise<SaveResult>`.

On final save only, merge selected models into native `models.json`; write the active key in Pi's native auth.json format ({type:'api_key',key: escapedLiteral}), preserving unrelated credentials/config. IMPORTANT discovered after initial draft: AuthStorage is NOT exported by Pi 1.4.0's public index and private subpath imports won't work in bundled Pi-Bolt. Use direct secure JSON merge for auth.json with a lock directory named auth.json.lock (the native store's proper-lockfile protocol), atomically replace the file, and preserve unrelated credentials. Do not import private host subpaths. Extra keys and skin metadata go in user-only `provider-adder.json`. Global default is settings.json.defaultProvider/defaultModel. If enabledModels already scopes the harness, append saved provider/model IDs preserving previous choices; if no scope exists, do not narrow the other providers. IDs must never silently overwrite a built-in/custom provider (raise a clear collision error, user can go back and rename). All saved files 0600, parent directories 0700 when newly created, atomic writes for JSON, validate entire draft and existing JSON before any writes, safe serialization against prototype keys, lock/best-effort rollback for a failed save. Read local existing file bytes only as needed for the operation, never log credentials. Use built-in filesystem APIs only; public host getAgentDir is available if needed. Never add a runtime dependency for locking. In models.json Google goes through google-generative-ai, no invented /generativecontent endpoint. Header values go through literalConfigValue. No raw key in models.json. Native auth store resolves literals: escape key strings too. SaveResult matches types.ts. Tests use temp dirs and dummy keys; preserve unrelated fields and cover cancellation/no write by wizard contract, collisions, defaults/scopes, normalization, permissions, corrupt config, literal key/header escaping.

## Wizard UI (UI worker)

Own `src/wizard.ts`, `tests/wizard.test.ts`. Export `runWizard(ctx: ExtensionCommandContext, initialDraft?: ProviderDraft): Promise<ProviderDraft | undefined>`. It must return only a confirmed draft; root command does storage. An optional initialDraft reopens Review after a failed save with every field retained. One native ctx.ui.custom screen manages Name → Base URL → Method → API keys → Header/Skin → Models → Review. Use active theme, built-in Input, Key/matchesKey, truncateToWidth, focus/cursor forwarding; keep simple and responsive on narrow terminals. Do not instantiate another renderer or use colors outside theme. Escape back keeps entered values, Enter forward, Escape at Name cancels. Form validation shown inline, retained draft across steps and manual model/header edit screens. Name may be blank and derive from host after URL entry. Mask all secret input/keys; paste, backspace and editing must work without ever returning raw keys in rendered lines. Key screen: initial key input, list with arrows selecting active key, N adds, D deletes selected, Ctrl+K checks selected key (abortable, visible status); at least one key required. Headers screen: Pi-Bolt default, Claude Code, Codex, OpenCode; allow N custom header name/value and D remove custom header, review actual headers. Models screen: Space fetch, arrows select row, A toggle highlighted, N manual model ID (and optional display name/context/output/reasoning/input metadata if feasible), Ctrl+A select all, Ctrl+E clear choices/default, Ctrl+D set highlighted as global default and include it, Ctrl+S or Enter advances to review requiring a nonempty selection. Do not fetch automatically. Review shows name, normalized URL, method, key count/active masked key, skin and custom header names (mask secretlike values), selected model count/default; final Enter returns confirmed draft. Escape goes back. All networking through network.ts; dispose aborts active work and ignores late completions; do not recreate the entire UI state after a failed request. Preserve selected manual models on subsequent fetches; context/output validated positive, output<=context. Render bounds and input behavior should have meaningful isolated tests with fake UI/fetch where possible.
